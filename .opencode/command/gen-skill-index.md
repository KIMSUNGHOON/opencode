prompt: |
  You are a documentation indexer that reads project documents and generates a SKILL.md knowledge index.

  ## Goal
  Scan the project's `docs/` directory (or a specified path), read every markdown file,
  produce a concise summary of each, and write a `SKILL.md` that inlines key summaries
  with explicit Read instructions for detailed documents.

  ## Execution Steps

  ### STEP 1: Parse Arguments & Locate Documents

  **Option Parsing:**
  - `$ARGUMENTS` contains a path → use that as the docs directory
  - `$ARGUMENTS` is empty → default to `docs/` relative to project root
  - `$ARGUMENTS` contains `--skill-name NAME` → use NAME instead of `project-knowledge`
  - `$ARGUMENTS` contains `--output DIR` → write SKILL.md to DIR instead of default
  - `$ARGUMENTS` contains `--force` → overwrite existing SKILL.md without confirmation

  **Locate project root:**
  ```bash
  PROJECT_ROOT=$(git rev-parse --show-toplevel 2>/dev/null || pwd)
  ```

  **Resolve docs directory:**
  ```
  DOCS_DIR = {PROJECT_ROOT}/{specified_path or "docs"}
  ```

  Verify DOCS_DIR exists. If not, report error and exit.

  **Set defaults:**
  ```
  SKILL_NAME = from --skill-name or "project-knowledge"
  OUTPUT_DIR = from --output or ".opencode/skills/{SKILL_NAME}"
  ```

  ### STEP 2: Scan & Read All Documents

  Find all markdown files:
  ```bash
  find {DOCS_DIR} -type f -name "*.md" | sort
  ```

  For EACH file found:
  1. Read the full content
  2. Extract:
     - **Title**: first `# heading` or filename
     - **Category**: infer from directory structure or content (e.g., architecture, api, domain, guide)
     - **Summary**: 2-4 sentence summary capturing the key points
     - **Key concepts**: list of important terms, entities, or decisions mentioned
     - **Token estimate**: rough size (small <500 tokens, medium 500-2000, large >2000)

  Store all results as `doc_index[]`.

  ### STEP 3: Generate SKILL.md

  Create the output directory:
  ```bash
  mkdir -p {OUTPUT_DIR}
  ```

  Write `{OUTPUT_DIR}/SKILL.md` with this structure:

  ```markdown
  ---
  name: {SKILL_NAME}
  description: "Project domain knowledge — {brief project description from docs}. Load this skill when working on tasks that require understanding of project architecture, domain models, API design, or business rules."
  ---

  # Project Knowledge Index

  > Auto-generated by `/gen-skill-index` from `{DOCS_DIR}/`
  > Generated at: {ISO8601 timestamp}
  > Source documents: {count} files

  ## Project Overview

  {2-3 paragraph synthesis of the project based on all documents read.
   Include: what the project does, key technologies, main architectural decisions.}

  ## Document Index

  | # | Document | Category | Size | Summary |
  |---|----------|----------|------|---------|
  | 1 | `{relative_path}` | {category} | {size} | {1-line summary} |
  | 2 | ... | ... | ... | ... |

  ## Key Concepts & Glossary

  | Term | Definition | Source |
  |------|-----------|--------|
  | {concept} | {brief definition} | `{source_doc}` |

  ## Domain Knowledge (Inlined Summaries)

  ### {Category 1}: {Title}
  > Source: `{relative_path}` — **Read this file for full details**

  {3-5 sentence summary with key points.
   Include important decisions, constraints, or rules.}

  ### {Category 2}: {Title}
  > Source: `{relative_path}` — **Read this file for full details**

  {3-5 sentence summary}

  (repeat for each document)

  ## Reading Instructions for AI Agents

  When working on a task related to this project, follow these steps:

  1. **Always read this SKILL.md first** — it provides an overview and index
  2. **Identify relevant documents** from the Document Index above
  3. **Read the full document** using the Read tool at the paths listed
  4. **Cross-reference** the Key Concepts table for domain terminology

  ### Quick Reference: Which Document to Read

  - Architecture questions → Read `{arch_doc_path}`
  - API design questions → Read `{api_doc_path}`
  - Domain model questions → Read `{domain_doc_path}`
  - Setup/configuration → Read `{setup_doc_path}`

  > All paths are relative to project root: `{PROJECT_ROOT}`
  > Use absolute paths when calling the Read tool.
  ```

  **Important rules for SKILL.md generation:**
  - Summaries must be substantive, not just "this document describes X"
  - Include actual decisions, patterns, and rules — not just topics
  - Key Concepts table should have real definitions, not placeholders
  - The "Quick Reference" section should map task types to specific documents
  - If a document is small (<500 tokens), inline its full content instead of summarizing
  - Keep total SKILL.md under 4000 tokens to stay within context budget

  ### STEP 4: Create Symlinks for Source Documents (Optional)

  If documents are in `docs/` and skill is in `.opencode/skills/`, the AI agent
  needs absolute paths to read them. The SKILL.md already contains absolute paths,
  so no symlinks are needed. But verify paths are correct:

  ```bash
  # Verify all referenced paths exist
  for path in {all_doc_paths}; do
    test -f "$path" || echo "WARNING: Missing document: $path"
  done
  ```

  ### STEP 5: Output Summary

  ```
  ═══════════════════════════════════════════════════════════════
  SKILL INDEX GENERATED: {SKILL_NAME}
  ═══════════════════════════════════════════════════════════════

  Source:      {DOCS_DIR}/ ({count} documents scanned)
  Output:      {OUTPUT_DIR}/SKILL.md
  Total size:  ~{token_estimate} tokens

  Key concepts extracted: {concept_count}

  The skill is now available as "{SKILL_NAME}".
  LLM agents will see it in <available_skills> and can load it

  To update after docs change:

  ```

  ## Error Handling

  - DOCS_DIR not found → print error with suggestion to specify path
  - No .md files found → print warning, check for other formats (.rst, .txt, .adoc)
  - Individual file read failure → skip file, note in summary
  - SKILL.md already exists and --force not set → show diff preview, ask to confirm

  | Option | Description |
  |--------|-------------|

# Generate Skill Index Command

**Input**: $ARGUMENTS

Scans project documentation and generates a SKILL.md knowledge index for AI agents.

## Usage

```bash
/gen-skill-index                           # Scan docs/, generate project-knowledge skill
/gen-skill-index wiki/                     # Scan wiki/ directory instead
/gen-skill-index --skill-name api-docs     # Custom skill name
/gen-skill-index docs/ --force             # Overwrite existing without prompt
/gen-skill-index --output .claude/skills/project-knowledge/  # Custom output location
```

## What It Does

1. **Scans** all `.md` files in the specified directory
2. **Reads** each document and extracts title, category, key concepts
3. **Summarizes** each document (2-4 sentences of substantive content)
4. **Generates** a SKILL.md with:
   - Project overview (synthesized from all docs)
   - Document index table
   - Key concepts & glossary
   - Inlined summaries for each document
   - Explicit Read instructions for AI agents

## How the Generated Skill Works

Once generated, the skill appears in `<available_skills>` for all AI agents.
When an agent loads the skill:

1. **SKILL.md content is injected** into context (summaries + index)
2. Agent sees which documents exist and what they contain
3. Agent uses **Read tool** to load full documents relevant to current task

This gives agents **awareness of all project knowledge** without loading
everything into context at once.

## When to Re-run

Re-run this command when:
- New documents are added to `docs/`
- Existing documents are significantly updated
- Project architecture or domain model changes
