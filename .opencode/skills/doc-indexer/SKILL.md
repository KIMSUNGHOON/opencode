# Doc Indexer — Project Knowledge Generator

Scans a documentation directory, reads every markdown file, extracts summaries and key concepts,
and generates a `project-knowledge` SKILL.md that gives AI agents awareness of all project domain knowledge.

## When to Use

- During `/analyze` when `docs/` directory exists
- When an agent needs project domain knowledge but `project-knowledge` skill doesn't exist yet
- When documentation has changed and the knowledge index needs updating
- When explicitly requested to index project documentation

## Procedure

### 1. Locate Documents

```
Default:    {PROJECT_ROOT}/docs/
Override:   specified path argument
Fallback:   check for wiki/, documentation/, doc/ if docs/ not found
```

Find all markdown files:
```bash
find {DOCS_DIR} -type f -name "*.md" | sort
```

If no `.md` files found, also check for `.rst`, `.txt`, `.adoc` formats.

### 2. Read & Analyze Each Document

For EACH markdown file found:

1. **Read** the full content using the Read tool
2. **Extract**:
   - **Title**: first `# heading` or derive from filename
   - **Category**: infer from directory structure or content
     - `architecture`, `api`, `domain`, `guide`, `setup`, `reference`, `adr` (decision record)
   - **Summary**: 2-4 sentences capturing actual decisions, rules, and patterns (NOT just "this document describes X")
   - **Key concepts**: important terms, entities, or decisions with brief definitions
   - **Token estimate**: small (<500), medium (500-2000), large (>2000)

### 3. Generate SKILL.md

Write to: `.opencode/skills/project-knowledge/SKILL.md`

**Structure:**

```markdown
---
name: project-knowledge
description: "Project domain knowledge — {brief description}. Load when working on tasks
  requiring understanding of project architecture, domain models, API design, or business rules."
---

# Project Knowledge Index

> Auto-generated by doc-indexer skill from `{DOCS_DIR}/`
> Generated at: {ISO8601}
> Source documents: {count} files

## Project Overview

{2-3 paragraph synthesis from all documents.
 What the project does, key technologies, main architectural decisions.}

## Document Index

| # | Document | Category | Size | Summary |
|---|----------|----------|------|---------|
| 1 | `{relative_path}` | {category} | {size} | {1-line summary} |

## Key Concepts & Glossary

| Term | Definition | Source |
|------|-----------|--------|
| {concept} | {brief definition} | `{source_doc}` |

## Domain Knowledge (Inlined Summaries)

### {Category}: {Title}
> Source: `{absolute_path}` — **Read this file for full details**

{3-5 sentence summary with key decisions, constraints, and rules.}

(repeat for each document, grouped by category)

## Reading Instructions for AI Agents

When working on tasks related to this project:

1. **This file gives you the overview** — summaries and index are already loaded
2. **Identify relevant documents** from the Document Index
3. **Use the Read tool** to load full documents at the absolute paths listed
4. **Cross-reference** the Key Concepts table for domain terminology

### Quick Reference: Which Document to Read

- Architecture questions → `{path}`
- API design questions → `{path}`
- Domain model questions → `{path}`
- Setup/configuration → `{path}`
```

### 4. Generation Rules

- If a document is **small (<500 tokens)**, inline its full content instead of summarizing
- Summaries must contain **actual content** — decisions, patterns, rules — not just topic descriptions
- Key Concepts must have **real definitions**, not placeholders
- Keep total SKILL.md **under 4000 tokens** to stay within context budget
- All document paths must be **absolute** for the Read tool
- Group documents by category for easier navigation

### 5. Cache Freshness

After generating, record metadata:
```json
// .opencode/skills/project-knowledge/.cache-meta.json
{
  "generated_at": "{ISO8601}",
  "source_dir": "{DOCS_DIR}",
  "document_count": {count},
  "documents": {
    "{relative_path}": {
      "title": "{title}",
      "category": "{category}",
      "size": "{small|medium|large}",
      "mtime": "{file_mtime_ISO8601}"
    }
  }
}
```

On subsequent runs, compare `mtime` to skip unchanged documents (incremental update).

### 6. Verify Output

```bash
ls -la .opencode/skills/project-knowledge/SKILL.md
```

If the file was created successfully, the `project-knowledge` skill will automatically
appear in `<available_skills>` for all agents.

## Error Handling

| Condition | Action |
|-----------|--------|
| Docs directory not found | Check fallback paths (wiki/, doc/, documentation/), report if all missing |
| No markdown files | Warn, check for other formats |
| Individual file read fails | Skip file, note in generation summary |
| SKILL.md already exists | Compare source mtimes, only regenerate if docs changed (unless --force) |
| Docs too large (>50 files) | Prioritize by directory depth and filename patterns (README first, then index, then alphabetical) |
