# Codebase Navigator — 3-Layer Knowledge Routing

Enables AI agents to navigate large codebases efficiently using pre-indexed knowledge layers.
Instead of reading hundreds of files, agents consult routing tables to find exactly what they need.

## Architecture

```
L1: project-map.yaml       →  Module overview (20-30 lines)
L2: modules/{name}.yaml    →  Per-module file/export/dep map (50-100 lines each)
L3: Source files            →  On-demand Read (only when needed)
```

**Context budget:** L1 (~500 tokens) + 2-3 L2 files (~300 tokens each) = ~1500 tokens
vs. reading all source files directly (~50K+ tokens)

## Cache Location

All cache files live under:
```
.opencode/workspace-cache/
  project-map.yaml          # L1: full project overview
  modules/
    {module-name}.yaml      # L2: per-module details
```

## How to Use (Step-by-Step)

### Step 1: Load L1 — Identify Relevant Modules

Read the project map to understand what modules exist and what they do:

```
Read: .opencode/workspace-cache/project-map.yaml
```

From L1, identify 2-3 modules most relevant to the question/task.

### Step 2: Load L2 — Find Specific Files

For each relevant module, read its detail file:

```
Read: .opencode/workspace-cache/modules/{module-name}.yaml
```

L2 contains:
- **files**: all source files with 1-line descriptions
- **exports**: key functions/classes/types exported
- **dependencies**: what other modules this imports from
- **entry_points**: where to start reading

### Step 3: Read L3 — On-Demand Source

Only now read the actual source files identified in Step 2.
Read specific line ranges when possible:

```
Read: src/skill/skill.ts (lines 1-50)    # Just the exports
Read: src/tool/task.ts (lines 80-120)    # Specific function
```

## Decision Tree: Which Layer to Consult

```
Question type?
├─ "What modules/components exist?"         → L1 only (no L2/L3 needed)
├─ "How does X module work?"                → L1 → L2 for X → L3 key files
├─ "Where is function/class Y defined?"     → L1 → L2 (check exports) → L3 exact file
├─ "How do A and B interact?"               → L1 → L2 for A and B → L3 connection points
├─ "Fix bug in feature Z"                   → L1 → L2 → L3 (read affected files)
└─ "Add feature to module X"               → L1 → L2 for X + neighbors → L3 implementation files
```

## L1 project-map.yaml Schema

```yaml
project:
  name: "project-name"
  type: "node|python|go|rust|..."
  description: "1-2 sentence project description"
  entry_points: ["src/index.ts", "src/main.ts"]

modules:
  - name: module-name
    path: src/module-name
    summary: "One line: what this module does"
    files: 8                              # file count
    tier: 1                               # 1=core, 2=support, 3=utility
    keywords: [key, domain, terms]        # for search matching
```

## L2 modules/{name}.yaml Schema

```yaml
module:
  name: module-name
  path: src/module-name
  summary: "2-3 sentence description of responsibility"

files:
  - path: src/module-name/index.ts
    description: "Main entry - re-exports public API"
    size: small                           # small/medium/large
  - path: src/module-name/core.ts
    description: "Core logic for X"
    size: medium

exports:
  - name: FunctionOrClass
    file: src/module-name/core.ts
    type: function|class|type|const
    description: "What it does"

dependencies:
  imports_from:                           # modules this depends on
    - config                              # reads config values
    - permission                          # checks permissions
  imported_by:                            # modules that depend on this
    - session                             # session loads this
    - tool                                # tool invokes this

entry_points:
  - file: src/module-name/index.ts
    reason: "Start here to understand the module"
  - file: src/module-name/core.ts
    reason: "Main business logic"
```

## Cache Freshness

Cache files include a `generated_at` timestamp. If the cache is older than the last git commit
touching that module, the agent should note this and optionally regenerate.

To check freshness:
```bash
git log -1 --format=%ci -- src/{module-name}/
```

## Generating Cache

Cache can be generated by:

1. **workspace-scanner agent** → produces L1 (project-map.yaml)
2. **module-analyzer agent** → produces L2 (modules/*.yaml)
3. **Manual creation** → write YAML files following the schemas above
4. **doc-indexer skill** → adds domain knowledge layer

## Performance Guidelines

- Never read more than 3 L2 files per question
- Never read more than 5 source files per question (use line ranges)
- If L1 doesn't exist, fall back to Glob + Grep (but suggest generating cache)
- If L2 doesn't exist for a module, do a quick Glob of the module directory
- Total context budget per navigation: aim for < 3000 tokens of file content
